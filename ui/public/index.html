    Model requests

    The gateway endpoint is looked up in the Capella control plane with this login. Without a login, set the gateway URL above.

    Control plane

    Creates a model API key through the Capella control plane, with the Control plane URL and Capella login above. It needs no gateway admin secret and no AWS access, so it also works for production. The key is saved in ~/.aigw-doctor/keys and reused for this organization and region until it expires (a day).

    Install a gateway build (to test a new build on this sandbox)

    Stops ai-gateway.service on the sandbox's gateway, saves the current binary as <binary>.bak-<time>, puts the build in place and starts the service with systemctl. If the service does not come up, the saved binary is put back. Check first shows the gateway's binary and how the build gets there, and changes nothing. The result appears under Results.

    Open a shell on the sandbox's AI Gateway or Couchbase node.

    Connects with aws ssm start-session and your AWS credentials (no SSH keys needed), or over SSH when .env sets <NAME>_AIGW_SSH / <NAME>_CB_SSH (with SSH_KEY if set). Both open a login shell as ec2-user (sudo su - ec2-user); set TERMINAL_USER in .env to change it, or none to keep the login user. The node is found from its ASG unless the form names its instance id.

    Create an API key (Capella control plane)

    The key gets access to every model in the region and is put into the API key field above. Capella shows it only once: without saving, it lives in this page only. The password and JWT are never saved. When the organization has a model in that region, its gateway endpoint fills an empty Gateway URL.

    System prompt
    Request headers (guardrails, deployment, more)

    One name=value per label, separated by commas. The gateway adds them to its Prometheus metrics for chat and embeddings requests, for the names on its allowlist (metricsCustomLabels; by default workflowId, appId, teamId, tenantId, sessionId) and ignores other names.

    The suppress headers apply to chat and embeddings; batch lines carry no headers, so a batch is always checked. X-cb-guardrail-response (error or inline) chooses how a batch reports a blocked input.

    Uses the gateway URL and API key choice from the form (a temporary key is created once and reused for up to an hour). Without a gateway URL, the endpoint found by the last run's control plane lookup is used.

    Talks to the gateway like any client: just its URL and an API key, so dev, stage and prod can be checked the same way. Connect shows its version (/v1/info) and the models the key can use (/v1/models). The key stays in this page and is never saved.
